# AI 모닝콜

정해 둔 시간이 되면 AI가 "전화를 걸어" 음성으로 대화하며 깨워 주는 서비스입니다. 웹 브라우저와 안드로이드 앱에서 쓸 수 있습니다.
AI는 [Ollama](https://ollama.com)로 내 컴퓨터에서 직접 돌리기 때문에 API 키나 비용이 들지 않습니다.

## 주요 기능

- **알람 설정**: 이름, 오늘 일정, 알람 시간, 사용할 AI 모델을 입력합니다.
- **AI 음성 통화**: 알람 시간이 되면 AI가 먼저 인사를 건넵니다. 브라우저 음성 합성(TTS)으로 말하고, 음성 인식(STT)으로 대답을 듣습니다. 마이크를 쓸 수 없으면 텍스트로도 대답할 수 있습니다.
- **4단계 대화**: 기상 확인 → 오늘 일정 안내 → 날씨 안내와 침대에서 나오기 → 마무리 순으로 진행됩니다.
  사용자의 대답을 "버팀 / 깸 / 침대에서 나옴 / 딴 얘기"로 분류해서, 실제로 일어났다고 할 때만 다음 단계로 넘어갑니다.
  버티거나 핑계를 대면 단계를 유지한 채 계속 깨웁니다.
- **사용자 말에 맞춘 대답**: 먼저 사용자가 한 말의 내용에 답하고(질문엔 답, 감정엔 공감, 이야기엔 대화), 그다음 일정·날씨·행동을 들어 깨웁니다.
- **누군가 깨워 주는 느낌**: 매 답변에 "전화 안 끊을 거예요", "목소리가 아직 잠겨 있네요"처럼 전화로 깨우는 중이라는 표현을 바꿔 가며 넣습니다.
- **사람 같은 반응 속도**: 답변을 다 만들기 전에 첫 구절부터 바로 말하기 시작합니다. 말을 끝낸 뒤 AI의 첫 소리까지 서버 기준 약 0.6초입니다.
- **대답이 없을 때**: 몇 초 동안 말이 없으면 다시 잠든 것으로 보고 AI가 이름을 부르며 다시 깨웁니다(최대 5번).
- **답변 품질 검사**: 반말, 영어·한자 섞임, "더 주무세요" 같은 포기 발언, 앞에서 한 말 반복을 문장 단위로 검사합니다.
- **빠른 첫 응답**: 알람 2분 전에 AI 모델을 미리 올려 두고, 벨이 울리는 동안 첫 인사를 미리 받아 둡니다.
- **끄기 방지**: 사용자가 일어났다고 AI가 판단해야 통화 종료 버튼이 활성화됩니다. 다시 알림(스누즈)을 누르면 5분 뒤에 또 울립니다.
- **날씨**: 브라우저 위치 정보로 [Open-Meteo](https://open-meteo.com)에서 현재 날씨를 가져옵니다. 위치 권한을 허용하지 않으면 서울 날씨를 씁니다.

## 구성

| 파일 | 설명 |
|---|---|
| `main.py` | FastAPI 백엔드. Ollama를 호출해 AI 답변을 만듭니다. |
| `static/index.html` | 프론트엔드 (알람 설정, 통화 화면, 음성 처리, 날씨). 웹과 안드로이드 앱이 같이 씁니다. |
| `android/` | 안드로이드 앱 (알람, 벨소리, 음성 합성·인식) |
| `requirements.txt` | Python 패키지 목록 |
| `run.bat` | Windows용 실행 스크립트 (패키지 설치 + 서버 실행) |
| `build-apk.bat` | 안드로이드 APK 빌드 스크립트 |

### API

| 메서드 | 경로 | 설명 |
|---|---|---|
| `GET` | `/` | 웹 화면 |
| `GET` | `/api/initial-message` | 알람이 울릴 때 AI가 건네는 첫 인사 |
| `POST` | `/api/chat/stream` | 대화 한 턴을 구절 단위로 보냅니다 (한 줄에 JSON 하나). `meta`(단계) → `sentence`(구절)… → `done` |
| `POST` | `/api/chat` | 대화 한 턴을 한 번에 돌려줍니다 (평가·호환용) |
| `GET` | `/api/models` | 설치된 Ollama 모델 목록 |
| `POST` | `/api/warmup` | 모델과 사용자 정보가 담긴 시스템 프롬프트를 미리 처리해 둡니다 |

## 설치하는 법

### 1. Python 설치

Python 3.10 이상이 필요합니다. <https://www.python.org/downloads/>에서 받을 수 있고, 설치할 때 **"Add Python to PATH"**를 체크하세요.

### 2. Ollama 설치

<https://ollama.com>에서 받아 설치합니다. winget을 쓴다면 아래 명령으로도 설치할 수 있습니다.

```powershell
winget install --id Ollama.Ollama -e
```

### 3. AI 모델 받기

기본 모델은 `gemma3:4b`(약 3.3GB)입니다. 더 가볍게 쓰려면 한국어 특화 모델 `exaone3.5:2.4b`(약 1.6GB)도 화면에서 고를 수 있습니다.

```powershell
ollama pull gemma3:4b
```

### 4. Python 패키지 설치

프로젝트 폴더에서 실행합니다.

```powershell
pip install -r requirements.txt
```

## 실행하는 법

1. **Ollama 실행**: Ollama 앱을 켜 두거나, 터미널을 하나 따로 열어 아래 명령을 실행합니다.

   ```powershell
   ollama serve
   ```

   이미 실행 중이라는 오류가 나오면 그대로 두면 됩니다.

2. **서버 실행**: 프로젝트 폴더의 `run.bat`을 더블클릭합니다. 터미널에서 직접 실행하려면 아래 명령을 씁니다.

   ```powershell
   python -m uvicorn main:app --host 0.0.0.0 --port 8000 --reload
   ```

3. **브라우저 접속**: <http://127.0.0.1:8000>을 엽니다.
   - Windows에서는 `localhost`로 접속하면 IPv6를 먼저 시도하느라 요청마다 약 2초가 늦어질 수 있어 `127.0.0.1`을 권장합니다.
   - 음성 인식이 잘 되는 **Chrome**이나 **Edge**를 권장합니다.
   - 마이크와 위치 권한을 허용해 주세요.
   - 알람이 울리기 전까지 브라우저 탭을 열어 두어야 합니다.

4. **종료**: 서버 터미널에서 `Ctrl + C`를 누릅니다.

## 설정

- **다른 모델 사용**: 웹 화면에서 모델을 고르거나, 환경 변수 `OLLAMA_MODEL`로 기본 모델을 바꿀 수 있습니다.

  ```powershell
  ollama pull exaone3.5:2.4b
  $env:OLLAMA_MODEL = "exaone3.5:2.4b"; python -m uvicorn main:app --port 8000
  ```

- **GPU 레이어 수**: 기본으로 모델의 모든 레이어를 GPU에 올립니다(`OLLAMA_NUM_GPU=99`). VRAM이 부족하면 자동으로 기본 설정으로 다시 시도합니다.
- `.env.example`에 있는 `ANTHROPIC_API_KEY`는 현재 코드에서 쓰지 않습니다.

## 안드로이드 앱

`android/` 폴더에 안드로이드 앱이 있습니다. 화면은 웹과 같은 `static/index.html`을 쓰고, AI는 PC 서버에 접속해서 씁니다.
웹에서 할 수 없는 기능은 안드로이드 기능으로 처리합니다.

- **알람**: 안드로이드 알람(`setAlarmClock`)으로 등록해서 화면이 꺼져 있거나 앱이 닫혀 있어도 울립니다. 잠금화면 위에 전화 화면이 뜨고, 재부팅해도 알람이 유지됩니다.
- **말하기·듣기**: 안드로이드 음성 합성(TTS)과 음성 인식을 씁니다. 안드로이드 WebView는 웹 음성 API를 지원하지 않습니다.
- **대답이 없을 때**: 몇 초 동안 말이 없으면 AI가 이름을 부르며 다시 깨웁니다(최대 5번). 웹에서도 같습니다.

### 앱 설치와 사용

1. PC에서 `run.bat`으로 서버를 켭니다. 폰이 접속할 수 있도록 Windows 방화벽에서 TCP 8000번 포트를 허용해야 합니다.
2. APK를 폰에 옮겨 설치합니다. "출처를 알 수 없는 앱 설치"를 허용해야 할 수 있습니다.
3. 앱을 처음 열면 마이크, 위치, 알림 권한을 허용합니다. Android 14 이상에서는 "전체 화면 알림"도 허용해야 잠금화면 위에 전화 화면이 뜹니다.
4. 알람을 설정합니다. PC 서버 주소는 APK를 빌드할 때 자동으로 들어가므로 입력할 필요가 없습니다. PC 주소가 바뀌었을 때만 설정 화면의 **고급 설정**에서 `http://<PC 주소>:8000`을 입력합니다.

서버의 AI 로직(`main.py`)을 고치면 PC 서버만 재시작하면 됩니다. 화면(`static/index.html`)이나 앱 코드(`android/`)를 고쳤을 때는 APK를 다시 빌드해 설치해야 합니다.

### APK 빌드

JDK 17, Android SDK(platform 34, build-tools 34.0.0), Gradle 8.7이 필요합니다. 프로젝트 폴더의 `build-apk.bat`을 실행하면 빌드한 뒤 바탕화면에 `AI모닝콜.apk`를 복사합니다.

```powershell
build-apk.bat                          # 이 PC의 주소를 앱 기본 서버 주소로 넣음
build-apk.bat http://192.168.0.10:8000 # 다른 주소를 넣을 때
```

- 경로에 한글이 있으면 안드로이드 빌드 도구가 실패할 수 있어서, 스크립트가 임시 영문 드라이브(`M:`)로 연결한 뒤 빌드합니다.
- JDK는 `C:\Program Files\Microsoft\jdk-17*`, SDK는 `%LOCALAPPDATA%\Android\Sdk`, Gradle은 `%LOCALAPPDATA%\Android\gradle`에서 찾습니다.

## 대화가 진행되는 방식

1. **대답 분류**: 사용자의 대답을 키워드 규칙으로 5가지 상태로 나눕니다.

   | 상태 | 예 | 단계 변화 |
   |---|---|---|
   | 버팀 (`sleepy`) | 5분만, 졸려, 재택하면 안 되나 | 그대로 (계속 깨움) |
   | 깸 (`awake`) | 일어났어, 깼어, 알았어 일어날게 | +1 (최대 2단계) |
   | 침대에서 나옴 (`up`) | 씻는 중, 세수하러 왔어, 옷 입었어 | 2단계로. 2단계에서 한 번 더 나오면 마무리 |
   | 대답 없음 (`silent`) | 몇 초 동안 말이 없음 | 그대로 (이름을 부르며 다시 깨움) |
   | 딴 얘기 (`other`) | 오늘 뭐 있지?, 영화 재밌었어 | 그대로 (답해 주고 다시 깨움) |

   규칙으로 판단하지 못한 대답은 "딴 얘기"로 처리합니다. 단계를 잘못 올리면 깨우기에 실패하므로, 모르면 단계를 올리지 않는 쪽을 택했습니다.
2. **프롬프트**: 상태별로 답하는 법과 단계별로 깨우는 법은 시스템 프롬프트에 표로 둡니다. 매 턴 사용자 말 뒤에는 `[지시] 유형: 버팀 / 단계: 2단계 / 느낌: …` 같은 이름표만 붙입니다.
   시스템 프롬프트와 이전 대화는 Ollama가 처리 결과를 재사용(캐시)하므로, 매 턴 새로 처리하는 부분을 짧게 유지하는 게 반응 속도의 핵심입니다.
   화면은 서버가 실제로 모델에 보낸 메시지(이름표 포함)를 대화 기록에 저장해 다음 턴에도 앞부분이 그대로 이어지게 합니다.
3. **스트리밍**: 모델이 만드는 문장을 쉼표나 문장 끝에서 끊어 구절 단위로 바로 보냅니다. 폰이 지금까지 받은 말을 다 읽기 전에 다음 말이 오지 않을 것 같으면, 문장부호를 기다리지 않고 띄어쓰기 위치에서 미리 보냅니다. 화면은 받은 구절을 음성 합성 대기열에 넣어 끊김 없이 이어 읽습니다.
4. **구절 검사**: 같은 문장의 앞부분과 이어 붙여 문장 단위로 검사합니다.
   - 첫 구절에 반말, 포기 발언, 외국어 같은 심각한 문제가 있으면 아직 아무 말도 안 했으므로 다시 생성합니다.
   - 이미 말하기 시작한 뒤에 그런 문제가 나오면 거기서 말을 멈추고 깨우는 말로 마무리합니다.
   - 앞에서 한 말을 되풀이하는 문장은 건너뜁니다.
   - 마무리 단계에서 통화를 끝내는 인사가 빠지면 코드가 붙입니다.

## 검증 결과

GTX 1050(VRAM 4GB), RAM 32GB, gemma3:4b 기준입니다.

### 반응 속도

통과 기준은 "사람이 말하는 속도로 알아듣고 말하는가"입니다.
- **반응 지연**: 사용자 말이 서버에 도착한 뒤 AI 첫 구절이 준비되기까지, 90%가 1.0초 이하 (사람 사이 대화의 말 차례 간격은 보통 0.2~1초)
- **끊김**: 첫 구절을 받자마자 읽기 시작할 때(8음절/초 가정), 자연스러운 쉼(문장 끝 0.35초, 쉼표 0.15초)을 넘는 멈춤이 0회

시나리오 4개(협조적, 버팀, 딴 얘기, 대답 없음), 17턴, 3회 측정:

| 지표 | 처음 (답변을 다 만든 뒤 전송) | 최종 (스트리밍) |
|---|---|---|
| 반응 지연 중간값 | 5.90초 | 0.60~0.65초 |
| 반응 지연 90% | 11.75초 | 0.72~0.82초 → 통과 |
| 반응 지연 최대 | 11.88초 | 0.87초 |
| 자연스러운 쉼을 넘는 끊김 | – | 0회 → 통과 |

이 값은 서버 처리 시간입니다. 폰의 음성 인식과 음성 합성에 걸리는 시간은 포함되어 있지 않습니다.

### 대화 품질

다양한 사용자 말(질문, 감정, 구체적인 이야기, 짧은 대답) 8턴으로 확인했습니다.
- 사용자 말에 맞춰 대답합니다. 예: "비 와? 우산 챙겨야 하나" → "네, 지금 흐리고 비가 오고 있네요. 우산 꼭 챙겨서 나가셔야 할 거예요!"
- 고정 대체 문장은 8턴 중 0~1회, "일어나셔야죠" 같은 상투적 재촉은 0~2회 나옵니다.
- 시나리오 17턴 기준으로 반말 0회, "깨우는 중" 표현이 들어간 답변은 11~16턴입니다.

### 대답 분류

규칙을 만들 때 보지 않은 새 표현 40개로 측정한 정확도는 24/40(60%)이고, 단계를 잘못 올린 경우가 4건입니다.
잘못 올라가도 "2단계에서 한 번 더 확인" 구조 때문에 한 번의 오판으로 통화가 끝나지는 않습니다.

### 모델 선택 (1차 개선 때)

시나리오 5개, 21턴 기준입니다. 이때 응답 시간은 측정 스크립트가 `localhost`로 접속해 턴마다 약 2초가 더 붙은 값입니다.

| 지표 | 처음 코드 (qwen2.5:3b) | 1차 개선 (gemma3:4b) |
|---|---|---|
| 단계 정확도 | 14/19 | 21/21 |
| "깨우는 중" 표현이 들어간 답변 | 26% | 86% |
| 포기 발언 ("더 주무세요" 등) | 1 | 0 |
| 영어·한자 섞임 | 0 (llama3.2는 7) | 0 |

## 한계

- **분류 정확도**: 키워드 규칙이라 처음 보는 표현은 약 60%만 맞힙니다. 모델로 분류해 보았지만 gemma3:4b는 40개 중 16개만 맞혀(대부분 "깸"으로 판단) 쓰지 않았습니다.
- **폰에서의 속도**: 반응 속도는 서버에서만 측정했습니다. 폰의 음성 인식(말 끝 0.8초 감지 포함)과 음성 합성 시간은 실제 기기에서 확인하지 못했습니다.
- **대답 품질**: 가끔 깨우는 말 없이 공감만 하고 끝나거나, "누구세요"에 정체를 밝히지 않거나, 첫 인사에서 시각 표현이 틀립니다("새벽 11시"). 같은 대화도 실행할 때마다 결과가 조금씩 다릅니다.
- **GPU 의존**: 반응 속도는 모델이 GPU에 모두 올라갔을 때 기준입니다. 첫 구절에 문제가 있어 다시 생성하는 턴은 1초를 넘을 수 있습니다.
- **PC 서버 필요**: 앱도 AI는 PC 서버에서 돌리므로, 아침에 PC와 서버가 켜져 있고 폰이 접속할 수 있어야 합니다.

## 문제 해결

| 증상 | 해결 |
|---|---|
| "Ollama가 실행되지 않고 있습니다" | `ollama serve`를 실행하거나 Ollama 앱을 켭니다. |
| "model not found" 오류 | `ollama pull gemma3:4b`로 모델을 받습니다. |
| 음성 인식이 안 됨 | Chrome이나 Edge를 쓰고 마이크 권한을 허용합니다. 안 되면 텍스트로 입력하세요. |
| `ollama` 명령을 찾을 수 없음 | Ollama를 설치한 뒤 터미널을 새로 엽니다. |
| 포트 8000을 이미 사용 중 | 명령의 `--port 8000`을 `--port 8001` 등으로 바꿉니다. |
